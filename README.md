# GAI3008-01 11주차 개인 과제 — 채팅 UI + 오류와 재시도

연세대학교 응용모바일프로그래밍 11주차 과제입니다. 제공된 `yonsei_gai3008_w11_lab1_chat_ui` 스타터를 기반으로 실습 1의 TODO 2~5와 실습 4를 완성했습니다.

## 구현한 기능

| 구분 | 구현 내용 |
| --- | --- |
| 실습 1 / TODO 1 | `ListView.builder(reverse: true)`로 메시지 목록 표시 (스타터 기반) |
| 실습 1 / TODO 2 | 사용자 말풍선 오른쪽, AI 말풍선 왼쪽 |
| 실습 1 / TODO 3 | `TextField`와 전송 버튼, Enter 전송, 빈 입력 방지 |
| 실습 1 / TODO 4 | 대화 삭제 후 `무엇이든 물어보세요` 빈 상태 표시 |
| 실습 1 / TODO 5 | `SafeArea`, `resizeToAvoidBottomInset`으로 키보드 대응 |
| 실습 4 | 401, 429, 500, timeout 오류 말풍선과 `다시 시도` 버튼 |

## 실행 방법

```bash
flutter pub get
flutter run -d chrome
```

테스트 실행:

```bash
flutter test
```

실제 Chrome 앱에서 채팅 UI, 429 오류 표시 및 `다시 시도` 기능을 직접 검증했습니다. 자동 위젯 테스트의 비동기 애니메이션/재시도 시점은 추가 확인이 필요합니다.

## 직접 확인 방법

1. 앱 실행 후 말풍선의 좌우 정렬 및 하단 입력창을 확인합니다.
2. 하단 입력창에 `안녕`을 보내면 타이핑 점을 표시한 후 모의 응답이 출력됩니다.
3. 상단 휴지통 버튼을 눌러 빈 상태 안내 문구를 확인합니다.
4. 상단 벌레 모양 메뉴에서 `429 · 요청 제한`을 선택하면 오류 말풍선이 나타납니다.
5. `다시 시도`를 눌러 1초 후 모의 응답으로 정상 복귀하는지 확인합니다.
6. 같은 메뉴에서 `401`, `500`, `timeout` 오류도 확인할 수 있습니다.
7. 메시지를 입력할 때 키보드가 올라와도 입력창이 가려지지 않는지 확인합니다.

> **주의:** 이 프로젝트는 스타터와 동일하게 실제 AI API를 연결하지 않았습니다. 오류와 재시도 흐름을 검증하기 위한 **모의 응답**을 사용하며 API 키는 포함하지 않습니다.

## 설계 의도

- 채팅 대기 상황을 타이핑 점으로 표시하여 앱의 현재 상태를 알 수 있도록 했습니다.
- 오류 발생 시 원인을 메시지로 알리고 `다시 시도`를 제공하여 사용자가 복구할 수 있게 했습니다.
- 애니메이션은 250ms 내로 처리하고, Reduce Motion 설정 시 필요한 정보는 그대로 제공하면서 움직임을 줄였습니다.
- API 키를 앱에 넣지 않아 프록시 API 연결 실습으로 확장하기 쉽도록 했습니다.
